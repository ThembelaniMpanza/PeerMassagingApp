# IP Messenger

**Author:** Thembelani.Mpanza

Local-first peer-to-peer messaging and file transfer for devices on the same LAN. The repository contains an Expo mobile app, a native Windows desktop app, an Electron prototype, and shared protocol packages.

## Architecture study

Open the [offline visual architecture guide](docs/architecture/index.html) or its [Markdown source](docs/architecture/ARCHITECTURE-STUDY.md). It includes eight diagrams, protocol and storage details, Windows/Android build explanations, and a searchable dependency inventory.

## Requirements

- Node.js 22 or newer
- npm 10 or newer
- Expo CLI tooling for mobile development
- A shared Wi-Fi or wired LAN for peer testing
- The native Windows executable requires no Node.js, npm, React, TypeScript, Electron, or web server.

## Install and Verify

```powershell
npm install
npm run verify
```

`npm run verify` runs TypeScript checks for every workspace and builds the desktop renderer, Electron main process, and preload bridge.

## Development

Start the desktop renderer:

```powershell
npm run dev:desktop
```

Start the Expo app:

```powershell
npm run dev:mobile
```

The mobile app requires a **native development build** because TCP/UDP sockets
are not included in Expo Go. Install Android Studio's SDK and Java 17+, start an
Android emulator, then build and install once (and again after native dependency changes):

```powershell
npm run build:mobile:android
```

For a standalone APK that can be installed on a phone without Metro, run
`powershell -ExecutionPolicy Bypass -File scripts/build-mobile-apk.ps1` after
generating the Android project. It writes `.artifacts/IP-Messenger-1.0.0-android.apk`
for arm64 phones and x86_64 emulators. This release-mode test APK uses Expo's
generated test signing key; it is intended for local testing, not store publishing.

For subsequent JavaScript development, open the installed app with:

```powershell
npm run dev:mobile:android
```

The mobile app uses Expo SDK 54 and React Native 0.81.5. Keep the terminal running
while using the development app. The localhost connection
uses ADB port forwarding. If port 8081 is already occupied, stop that development
server first. After changing dependency resolution, append `-- --clear` to the
command to rebuild Metro's cache.

The Expo app lives in `apps/mobile`; the Flutter project in the repository root
is a separate implementation. Expo's `autolinkingModuleResolution` setting keeps
the mobile bundle on its own React and React Native versions in this workspace.
Mobile uses real UDP discovery on port 5051 and TCP messaging on port 5050.
Select a discovered peer and connect, or enter its IPv4 address and port. Pairing
requires approval on the receiving device: compare the fingerprints, then enter
the sender's six-digit code. Paired devices can exchange encrypted messages and
files. Messages queue while disconnected and retry after reconnecting. Received
files are verified, saved in the app's documents folder, and can be exported using
"Save or share". Incoming files require explicit acceptance.

Identity, trusted peers, and session keys use SecureStore; message and transfer
history use local AsyncStorage. Message history is not encrypted at rest. File
transfers are currently limited to 10 MB and four concurrent incoming offers,
with a 60-second inactivity timeout. Interrupted files must be sent again. Keep
both apps in the foreground; background services and background discovery are
not implemented. iOS native configuration is included but Android is the tested
platform; iOS broadcast discovery may require Apple's multicast entitlement.

The WPF app in `apps/windows-native` implements the mobile protocol: live UDP
discovery, P-256 pairing, AES-GCM messages with delivery/read receipts, and
encrypted file transfers with explicit acceptance and SHA-256 verification.
The Electron prototype still has sample discovery.

### Emulator smoke test

```powershell
npm run test:peer
npm run dev:test-peer
```

The test peer listens on TCP 5052 and broadcasts UDP 5051. In the Android emulator,
connect to `10.0.2.2:5052` (the host PC), pair, and send a message. This **test-only**
peer automatically approves pairing, echoes messages, offers a small text file,
and accepts uploaded files with checksum verification logged in the terminal.
Stop it with Ctrl+C after testing. It is not a production desktop app.

Emulator NAT can block LAN broadcasts. Manual IP connection remains available;
physical devices on the same Wi-Fi use broadcast discovery. No firewall changes
are made automatically. For physical-device testing, allow private-network TCP
5050 (5052 for the test peer) and UDP 5051. Native Android/iOS directories under
`apps/mobile` are generated by Expo prebuild and excluded from source control.

Build the native Windows desktop executable:

```powershell
npm run build:native-windows
```

Run:

```text
apps/windows-native/publish/IPMessenger.exe
```

This is a self-contained WPF application. Its LAN listener is a direct TCP socket, not an HTTP or development web server. Discovery uses UDP broadcast, so internet access is not required when devices share Wi-Fi or wired LAN.

Exit the running desktop app using its tray menu before publishing over its
executable. Building requires the .NET 10 SDK; running the published app does not.
The desktop saves identity, conversations, and transfer history under
`%LOCALAPPDATA%\IPMessenger`. Pairing keys are protected with Windows DPAPI for
the current account. Received files are saved in its `Received` subfolder; use
**Show saved file** to reveal a completed download. Interrupted transfers can be
sent again. Closing the window keeps the listener running in the system tray.

To connect the Android emulator to the native desktop, enter `10.0.2.2:5050`
in the mobile app. Alternatively, run `adb forward tcp:15050 tcp:5050`, then
connect the desktop to `127.0.0.1:15050`. Emulator NAT blocks ordinary LAN
broadcast discovery, so use one of these direct connections. Select **Pair
device**, compare the fingerprint, and enter the displayed code on the receiving
device within 30 seconds. Both apps must approve incoming files explicitly.

Run the Windows/mobile protocol compatibility test on Windows with:

```powershell
npm run test:native
```

It uses actual TCP sockets and the production C# backend to check encrypted
Unicode chat, bidirectional multi-chunk and empty files, rejected offers, and
identity/trust persistence across restart. Test auto-approval exists only in the
separate console harness, never in the installed desktop app.

The desktop Electron shell expects the Vite renderer at `http://127.0.0.1:5173` during development. The production build loads the bundled renderer from `apps/desktop/dist` and the Electron main process from `apps/desktop/dist-electron`.

## Architecture

- `apps/desktop`: Electron main process, secure preload bridge, React renderer, TCP server, and desktop adapters.
- `apps/windows-native`: Native WPF Windows application with direct UDP discovery, TCP messaging, file picker, notifications, and system tray support.
- `apps/mobile`: Native Expo app with TCP/UDP adapters, pairing approval, encrypted chat, file picker, transfer controls, and local storage.
- `packages/protocol`: Runtime-validated newline-framed protocol events and payloads.
- `packages/networking`: Peer socket abstraction, HELLO handshake, ping/pong, bounded connection retries, and accepted-socket support.
- `packages/shared`: Identity, discovery, pairing, encrypted sessions, messages, queues, and file transfers.
- `packages/models`: Shared device, conversation, message, and file-transfer models.

## Network and Security

- Default TCP port: `5050`.
- Traffic is intended for trusted same-LAN peers.
- Pairing verifies a six-digit code and displays a public-key fingerprint.
- Messages and file chunks use AES-GCM after ECDH pairing.
- Trusted-device metadata and session keys are stored locally. No cloud service is required.
- Malformed frames, oversized frames, checksum failures, timeouts, and connection failures are rejected or surfaced as explicit states.

## Manual LAN Check

1. Run the native Windows app and a mobile development build on the same LAN (or use two mobile devices).
2. Allow TCP port `5050` and UDP `5051` through any private-network firewall (`5052` for the test peer).
3. Confirm each device appears in discovery.
4. Request pairing and compare the displayed verification code and fingerprint.
5. Send a message and a small file after approval.
6. Disconnect one peer, queue a message, reconnect, and verify delivery. Interrupted files must be selected and sent again.

## Troubleshooting

- No peers appear: confirm both devices are on the same network and discovery is running.
- Connection timeout: check the peer IP, TCP `5050`, and Windows/macOS firewall rules.
- Messages remain queued: complete pairing first; secure mode does not send plaintext to untrusted peers.
- Interrupted transfer: select the original file and send it again; partial file resume is not implemented.
- Desktop production launch fails: run `npm run build:desktop` and launch the generated Electron main artifact from `apps/desktop/dist-electron`.
